# 01 — Basics

## What this demonstrates
The exact command surface for ultrareview (`/code-review ultra`, and its
non-interactive `claude ultrareview` subcommand) — a cloud-based,
multi-agent code review with independently-verified findings — documented
here rather than actually run, since each run costs a real, limited
resource on your account.

## Why it matters
This is Claude Code's cloud-native counterpart to the local `/code-review`
command already cataloged in example 03's built-in commands reference:
higher signal (every finding independently reproduced and verified),
broader coverage (a larger reviewer-agent fleet), and it runs entirely off
your machine. Worth knowing the command shape even before you spend a run
on it.

## Prerequisites
A claude.ai account sign-in (not just an API key) — run `/login` first if
you're on API-key auth. Not available on Bedrock/GCP Agent Platform/Foundry
or for organizations with Zero Data Retention enabled.

## Not run live here, on purpose
Ultrareview is metered: Pro and Max accounts get 3 free runs total, ever —
a one-time allotment that doesn't refresh — and Team/Enterprise get none
free. After that, each run bills roughly $5-$25 in usage credits. Running
this "as a demo" would permanently spend one of your 3 free lifetime runs
(or real money) reviewing this repo's own trivial example files, which
isn't a good trade — so this folder documents the exact commands rather
than invoking them.

## Steps to reproduce
From any git repository (this one or a real project):
1. Make sure you're signed in with claude.ai (`/login` if you're on
   API-key auth only — see Prerequisites).
2. Run one of, depending on what you want reviewed:
   ```
   /code-review ultra                        # current branch vs default branch
   /code-review ultra develop                # review against a specific base branch
   /code-review ultra 1234                   # review GitHub PR #1234
   /code-review ultra check my auth changes  # plain-language note, same scope as no-arg
   ```
3. Read the confirmation dialog Claude Code shows before launching — it
   states the review scope, your remaining free runs, and the estimated
   cost. Only confirm once you're ready to spend that run.
4. The review continues in the background (roughly 5-10 minutes) while
   your session stays usable; check `/tasks` for running/completed reviews.
5. For CI/scripts instead of an interactive session, see
   `sample-non-interactive.sh` in this folder for the `claude ultrareview`
   subcommand shape, which blocks until findings are ready and prints them
   to stdout.

## Expected result
When the review finishes, Claude Code shows the verified findings as a
notification in your session: each finding names a file location and
explains the issue, and — unlike a quick local `/code-review` — every
finding has already been independently reproduced and verified by a second
agent, so what you get is fewer, higher-confidence issues rather than a
long list of style nits. If you opted to post (`--post`), the findings also
land as a single plain PR comment from your own GitHub account, ending with
a "Generated by Claude Code" note — never posted without you choosing to on
that run.

## Gotchas / notes
- Ultrareview is a research-preview feature — command, pricing, and
  availability may change.
- A diff over 500 changed files or 8,000 changed lines (current defaults,
  may change) gets refused rather than reviewed partially.
- Posting findings to a PR (`--post`) comments as *you*, from your
  connected GitHub account, and is opt-in per run — never automatic.
- Compare with plain `/code-review` (already in example 03's built-in
  commands reference): that one runs locally, free, in seconds to minutes;
  this one runs remotely, costs real usage after your free runs, and takes
  roughly 5-10 minutes.
